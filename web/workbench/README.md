# 开发流程工作台

在团队仓库的 `web/workbench/` 下运行以下命令。页面默认展示团队“设备预约”v2 样例的审核前运行快照。

```powershell
npm.cmd ci
npm.cmd run dev
npm.cmd run build
npm.cmd test
npm.cmd run lint
```

建议使用 Node.js 22.12 或以上版本。开发地址以 Vite 终端输出为准（默认 `http://localhost:5173`）。

### v2 局部联调

默认使用 Mock。使用已有测试项目时，在当前 PowerShell 会话设置以下环境变量后启动。

```powershell
$env:VITE_WORKBENCH_MODE = 'v2'
$env:WORKBENCH_PROXY_TARGET = 'http://127.0.0.1:8008'
$env:VITE_WORKBENCH_PROJECT_ID = '<测试项目 ID>'
# 仅在明确授权写入该测试计划时设置
$env:VITE_WORKBENCH_PLAN_ID = '<测试计划 ID>'
npm.cmd run dev
```

Vite 开发和预览服务可代理 `/api/v2`。生产部署可由同源反向代理提供该路径，或在构建时设置 `VITE_WORKBENCH_API_BASE` 为允许跨域请求的服务源。Vite 客户端环境变量不存放密钥。

真实 v2 模式下，项目 GET 返回 404 时显示阻塞原因并停止启动。计划 404、网络错误、超时和非法响应也会显示失败。需要演示时显式设置 VITE_WORKBENCH_MODE=mock 并重新启动 Vite。真实局部模式只开放计划读取和授权 PATCH，事件分页可由独立 API 客户端验证。

当前联调仍依赖团队补齐标准项目、需求、赛马和规格接口，确认计划创建如何调用分解器，并统一运行任务数组、单步回包、产物字段及审核键。动态小组也需对齐后接入。

- `src/components/`：阶段导航、主视图区、只读依赖图与任务详情、阶段信息栏和活动记录。
- `src/types/v2.ts` 定义接口数据，`src/types/workbench.ts` 定义展示模型。Dagre 只负责依赖图的布局。
- Mock 直接读取 [团队 v2 场景](../../examples/v2/scenario.json)，其中审核前快照的事件游标是 9，样例提供的批准事件序号是 10，因此初始活动记录为空。
- `src/api/` 中的 Mock 和 HTTP 适配器使用同一套展示映射。HTTP 适配器提供需求提交、赛马、规格保存与确认，以及已有的只读查询。页面当前默认使用 Mock。

本地可以从「需求录入」载入团队样例并提交新版本，或用该需求新建项目。赛马首次演示 A 组先完成、B 组失败，通过「重试失败组」继续。两组就绪后，从「评审与整合」选择方案、保存草稿并确认。Mock 在内存中保存版本，刷新恢复示例。它只回放团队 fixture 的需求条目及出案结果，其他 Markdown 可保存但不会生成分析结果。

进入「Workflow 编排」或「开发执行」可查看只读依赖图。拖动空白处平移，也可以用画布按钮缩放或适应视图。图中节点、任务列表和详情共用选中任务。关键标记只读取排期中的 `critical` 字段，连线表示直接前置关系。

「任务配置」编辑最新版计划。保存使用 v2 PATCH，已有运行仍绑定原版。版本冲突时可核对最新版，再显式应用本地草稿。「甘特图」展示已返回的计划排期与各次执行尝试时间。Mock 保存后生成新版本，排期为空，且只回放团队样例中的成环错误。通用校验与新排期由后端提供。

在「Workflow 编排」或「开发执行」右侧可启动、查看及控制运行。已有运行的控制请求携带修订号，所有写请求使用幂等键。运行监控从当前游标读取增量事件，断线会重试，任务选择可在同一浏览器会话的页面刷新后恢复。

「载入执行控制演示」创建独立的样例项目，可手动逐批或自动回放团队样例中的缺项、失败阻塞、独立任务回报及待审产物。默认样例也可直接进入「交付审阅」，选择 T2 后批准、修订并批准或退回。Mock 回放到 T4 就绪或受阻。SHA 的提交归属和可达性由真实 v2 后端验证。v1 演示使用原有的 `web/index.html`。

### 项目隔离与版本引用

同一工作台会话内的需求、规格、计划和审核草稿按项目隔离。审核草稿还按运行和任务隔离，原有版本冲突及显式重基准机制继续有效。切回同一项目可恢复内存草稿；更换 API 数据源或刷新页面会清空内存草稿。任务选中记录在会话存储中按 Mock/v2 与项目分开。

集成调用方可以传入 App 的 projectId 作为当前项目。现有默认入口保持原有导航；真实局部连接只允许读取配置项目，不提供项目列表或跨项目切换入口。项目切换后旧请求结果不再应用，运行游标从新快照初始化。真实项目入口和运行审核契约仍需团队补齐。

### 轮询与恢复

监控离线时暂停；在线后先尝试读取当前项目快照，再从已确认游标补读事件。快照恢复与事件游标分别提交：如果事件缺页，保留最后有效快照，使用原游标重读，直到收到连续记录。HTTP 层依照契约拒绝非法排序和分页结构。轮询失败按指数退避，持续失败时每 30 秒做一次低频探测。项目、模式或组件切换会废弃旧读取及定时器。

写入响应丢失时可显式重试相同请求，客户端在同一适配器会话内复用原 Idempotency-Key；轮询不会自动提交写操作。409 会刷新快照并保留本地草稿。标准项目入口及运行审核契约尚待后端对齐，恢复路径的 UI 测试使用测试数据。
