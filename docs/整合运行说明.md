# 整合运行说明

## 启动

需要 Python 3.10+。真实代码执行还需要 Git。

```bash
python -m se_agent.workbench --port 8008
python -m unittest discover -s tests -v
```

浏览器打开 http://127.0.0.1:8008。可通过 `--db data/example.sqlite3` 指定数据库。

## 各分支交接

| 来源 | 接入内容 | 主要入口 |
|---|---|---|
| CLY | 需求快照、多组差异化提示词、独立出案、重跑 | `intake.py` |
| HSX | 独立评价、方案整合、决策编辑、确认与版本记录 | `synthesis.py`、`synthesis_preview.py` |
| QLM | 工作台布局、任务分解、计划同源导出、领域记忆 | `planner.py`、`domain_memory.py` |
| ZXQ | DAG 校验、并发与路径冲突排期、SQLite 运行状态、租约与审核 | `store.py`、`schedule.py`、`api_v2.py` |
| Hza | 高低配模型路由、Worker、Git worktree、AutoGen 适配 | `worker.py`、`worktree.py` |
| integration/memory-unification | QLM 记忆与 ZXQ Store 共用连接、事务及旧数据迁移 | `Store.memory`、`memory_migration.py` |

`workspace.py` 负责模块之间的数据转换与运行派发，`workbench.py` 提供统一 HTTP 服务。QLM 原有页面中的模块、卡片、左侧分级目录、图画布和主理栏承载实际交互。

## 项目主理人（默认入口）

提交一份需求即可启动。左侧常驻需求、评审、任务分解和开发执行等入口，会显示当前对话的阶段状态。可以随时进入查看。若需要手改方案或任务，打开对应阶段的确认点，保存后交回主理人；主理人会接着使用已保存的规格或计划。已经启动的执行继续绑定原计划版本。

主理人决定分几组并为每组生成不同的提示词，各组在独立上下文里出案。独立评审与合并后，主理人以明确需求为边界，生成可撤销的原型决定，完成校验后自动确认规格、分解任务、排期并派发。默认只展示综合方案、任务和交付，不展示各组草案。自动复核记录实际检查理由，模型复核不是测试已经通过的证明。

- 运行中可以说「暂停」「继续」「任务到哪一步了」。说「修改……」会保留旧一轮，带新要求启动下一轮。流程需要人工介入时，仅在用户启用的规格、开工或交付确认点暂停；真实错误会明确说明，不把它伪装成等待人填表。
- 高级设置可以指定并发、组数、逐组提示词、流程偏好、开发模式及产物目录；这些设置应用到本轮重跑。确认点可随时在对话或高级设置中改变。
- 有 API 时自动模式进行真实开发，空白产物位置默认创建独立的 `SE-Agent-Projects` 子仓库；可修改到自己选定的目录。不配置 API 时运行离线演示，不生成真实源代码。开发不自动推送到 GitHub。
- 主理记录和阶段检查点保存在项目数据库。重启后停止继续派发，用户明确继续后从保存阶段恢复。手动工作台仍可用于核对分解、依赖图和甘特图。

## 完整流程（高级手动工具）

1. 输入 Markdown，确认同版需求快照。每个小组配置自己的提示词，可增加讨论组。
2. 各组独立出案。全部提交后公开草案，交接完整需求和所有草案。失败组可单独重试。
3. 分别生成评价，选择融合或以某组方案为起点。人工处理待决问题、修改决策并保存新版本，再确认规格。
4. 确认规格交给 QLM 分解器。任务关联需求、决策、待决项、完成条件、预计产物和前置依赖。
5. 编辑任务名称、角色、估时、审核要求、写入范围和输出。在保存时调用编排校验，再生成甘特排期。
6. 启动手动或自动开发。手动模式通过主理栏推进一批任务。自动模式根据依赖、空闲槽和写入范围派发。
7. 在任务详情补充输入、检查产物、修改文本、批准或退回。批准后的产物版本进入下游 Worker 的输入。
8. 完成后可记录具体踩坑经验，人工审核发布，在项目经验基线中按领域、关键词和同义词检索。

## 选择产物位置、看进度、处理卡点

- 交接评审后，点顶部「产物位置」，填写绝对路径。状态和版本仍保存在工作台数据库；点「导出项目文件」会在所选位置生成该项目专用目录，包含需求、规格、计划和已批准的文本产物。
- 勾选「绑定为真实代码仓库」可使用现有 Git 仓库或初始化一个空目录。已有模拟计划会保留原任务并形成绑定基线的新版本，旧运行仍指向旧版。暂停会保留任务，空闲时可结束旧运行后启动新版本。代码提交留在目标仓库的任务分支，详情显示提交号和改动文件；不会向远端推送。
- 顶部运行条显示当前动作、已用时间、最近的执行事件、真正运行的任务和卡点。执行页的预计剩余时间来自计划，只在运行时显示；等输入或审核时不提供倒计时。
- 「主理人整合方案」自动组织独立评审并生成综合草稿。自动开发会先处理可逆的实现细节，并记录主理人来源。重要业务问题一次展示一个，可以点候选方式或用一句话答复；同一个答案应用到相关任务。常规开发产物经过结构和写入范围检查后可自动放行，敏感和最终交付仍保留人工审阅。
- 顶部「使用答疑 AI」能根据工作台说明回答如何保存、启动、暂停或处理卡点。已知问题直接使用当前版本的说明，其他问题可由配置的模型结合说明回答。

## 甘特图与人工操作

- 时间单位为分钟，接口存储整数秒。时间条显示任务持续时间，悬浮查看起止时间。
- 连线来自 `depends_on`，琥珀色使用排期器返回的 `critical`。
- 排期考虑并发上限与写入路径冲突。关键路径按纯依赖图计算。
- 任务页编辑完成后点击「保存任务清单」。甘特图与 `workflow.json`、`task.md` 使用同一计划版本。
- 点击时间条可定位任务编辑。任务详情支持修改完成条件、路径、输出类型和来源编号。
- 工作台显示本次运行所绑定的计划。人工在任务页保存后续版本时，本次运行继续使用其启动版本。
- 主理栏提供阶段检查、定位问题、追加小组指令、退回返工、单步、暂停和继续。检查结果与人工修改均来自当前项目数据。

## 数据与恢复

统一服务使用 QLM/ZXQ 的 SQLite Store。评审历史通过项目快照保存，确认规格转换为编排器的结构化规格，计划及运行由 Store 管理。

Worker 输入包含直接前置任务每个输出的最新已批准产物，以及固定规格版本关联的需求和决策。文本产物包含正文，代码产物包含提交号和改动路径。人工修订形成新产物版本。

项目、运行、尝试和产物编号能跨项目共存。写操作检查版本，运行事件与状态在同一事务更新。服务重启后，未完成尝试依照原租约恢复处理。

经验记录保存问题、原因、触发条件、改正步骤、验证条件、关键词与来源。候选经验初始证据等级为 `pending`，负责人审核发布后可纳入经验基线。验证等级与发布状态分别记录。

## 模型和真实代码执行

赛马及评审的模型配置沿用 CLY 接口。

```powershell
$env:SE_AGENT_BASE_URL = "<兼容 Chat Completions 的服务地址>/v1"
$env:SE_AGENT_MODEL = "<赛马及评审模型>"
$env:SE_AGENT_API_KEY = "<本机配置的密钥>"
```

开发执行使用 Hza 的路由配置。复制 `se_agent/model_config.json`，填写高、低两档模型及各自供应商地址，然后指定配置文件和目标仓库。

```powershell
$env:SE_AGENT_MODEL_CONFIG = "C:\配置目录\model_config.json"
$env:SE_AGENT_REPO = "C:\项目目录\目标Git仓库"
$env:SE_AGENT_MODE = "real"
python -m se_agent.workbench --port 8008
```

每个档位通过 `api_key_env` 指定凭证所在的环境变量。高能力模型用于规划、复核和集成。配置中的复杂任务先生成实现边界，低成本模型接收该边界后按输出逐项生成。

真实计划绑定目标仓库的完整基线提交。Worker 在独立 worktree 纳入已批准上游提交，再生成文件与 Git 提交。服务端校验提交可读性、继承关系和写入范围。代码产物可在任务详情填写人工修订提交并审核。

`SE_AGENT_EXECUTOR=autogen` 启用既有 AutoGen 0.2 适配器，需要对应依赖。默认执行器使用兼容接口直接调用模型。

当前分解为确定性基线，模板估时和默认路径需要人工核对。默认预览为离线模拟，真实模型输出质量需要使用实际模型配置进行验收。

## 服务入口

| 路径 | 功能 |
|---|---|
| `/` | QLM 统一工作台 |
| `/preview/config`、`/preview/snapshot`、`/preview/group` | 需求和组内出案 |
| `/preview/projects/...` | HSX 评审、编辑、确认和历史 |
| `/preview/plans`、`/preview/plans/edit` | QLM 分解与 Store 版本化计划交接 |
| `/workspace/projects/{id}` | 已保存评审、最新计划与运行 |
| `/workspace/projects/{id}/runs/...` | 派发执行、人工审核与输入补充 |
| `/workspace/projects/{id}/memory/...` | 候选经验、审核发布与基线更新 |
| `/api/v2/...` | ZXQ 计划、运行与事件接口 |

运行及记忆写接口要求 `Idempotency-Key`，运行控制同时检查 `expected_revision`。本地服务绑定 `127.0.0.1`，使用服务端固定的本地负责人身份。密钥通过环境变量传入。
