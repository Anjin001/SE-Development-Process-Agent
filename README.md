# SE-Development-Process-Agent

第五组可运行的并行开发骨架。使用 Python 3.10+ 标准库，浏览器直接访问，无需安装依赖或配置模型密钥。

```bash
python -m se_agent.server --port 8000
python -m unittest discover -s tests -v
```

用浏览器打开 http://127.0.0.1:8000。保留默认需求，点击「生成两份草案」→「确认融合方案」→「确认并启动」。推进两轮后，T2 进入人工审核，T3 独立完成。修改 T2 产物并批准，再推进一轮。T4 的产物会显示它读取了 T2@v2。也可以退回 T2，再重试。

- [下一轮 v2 联调契约](docs/接口契约-v2.md) · [v2 正常与异常样例](examples/v2/scenario.json)

当前是本地模拟。两份草案、评分与任务由模板生成，Worker 返回文本。状态存于进程内、重启会清空。并发上限控制一轮选取多少任务，模拟调用按顺序完成。这个版本用来确认交接和人工审核流程。

## 赛马与评审联动预览

```bash
python -m se_agent.workbench_preview --port 8003
```

打开 http://127.0.0.1:8003，确认需求快照，设置提示词并启动赛马。草案齐备后点击「进入评审与整合」，同版需求与所有参赛组草案会自动交接。再生成独立评价、选定任一组或融合，人工检查并确认，最后下载规格 JSON 或 Markdown。

左侧目录可在赛马和评审之间切换，保留本次页面上的输入。赛马主理人可以暂停派发、给指定组补充指令并单独重跑。评审主理人可以检查当前编辑、定位未决事项，也能把返工指令送回指定小组，由人工确认是否应用。同一需求快照的返工会递增评审轮次，在「版本与记录」中保留旧方案、原草案和本轮主张差异。不同候选做法会列成议题。采用选项或填写人工答复并写入决策后，保存时由服务端生成正文。评审数据存于内存。

### 接入生成与评审模型

默认是离线模拟。配置兼容 Chat Completions JSON 模式的服务后，独立构思、组内质疑、草案、评分与整合都使用模型。每组调用只接收自己的提示词，评审独立接收一份草案。出错后显示失败并支持重试。

以下示例中的模型名需替换成你自己的模型。

```powershell
$env:SE_AGENT_BASE_URL = "http://127.0.0.1:11434/v1"
$env:SE_AGENT_MODEL = "<已安装或可调用的模型名>"
python -m se_agent.workbench_preview --port 8003
```

需要鉴权时在本机配置 `SE_AGENT_API_KEY`。配置地址后，当前需求与草案会发送给该模型服务。接口格式参考 [Ollama 官方兼容文档](https://github.com/ollama/ollama/blob/main/docs/api/openai-compatibility.mdx)。
