# SE-Development-Process-Agent

第五组多智能体软件开发工作台。界面沿用 QLM 设计，整合需求赛马、评审、任务分解、编排执行、人工审核与领域记忆。离线演示使用 Python 3.10+ 标准库。

```bash
python -m se_agent.workbench --port 8008
python -m unittest discover -s tests -v
```

打开 http://127.0.0.1:8008，默认进入「项目主理人」。发一句需求即可从多组独立出案、评审和补齐决策一路推进到任务编排、开发和交付。工作台展示执行状态及综合方案，默认不弹人工确认。可以在对话中说暂停、继续、重试或修改需求，也可以在高级设置里开启确认点、覆盖分组提示词和配置产物位置。原来的任务图、甘特图和手动编辑仍可按需打开。

任务分解页直接显示甘特图，以分钟呈现开始时间、持续时间、依赖连线与关键路径。编辑估时、依赖或并发上限并保存后，会调用 ZXQ 排期器重算。点击时间条可定位任务编辑区。开发工作台的进度页也显示运行所绑定计划的甘特图。

默认数据库为 `data/workbench.sqlite3`，可用 `--db` 指定。顶部项目菜单可恢复历史项目，数据库中保存评审版本、计划、运行记录与经验。运行绑定启动时的计划版本，后续计划编辑可形成新版本。页面样式库随项目提供。

详细启动与模块交接说明见 [整合运行说明](docs/整合运行说明.md)。

- [下一轮 v2 联调契约](docs/接口契约-v2.md) · [v2 正常与异常样例](examples/v2/scenario.json)

默认使用离线模拟。点击顶部「配置 API」或左侧「高低配模型路由」，可填写 API 基础地址、API Key 和模型 ID，测试连接后保存。界面设置在服务重启后恢复为启动配置。启用真实代码执行还需要配置目标 Git 仓库。QLM 分解器按结构化需求生成确定性任务，估时和建议文件路径需要负责人核对。

启动时会自动读取项目根目录的 `.env`（模板见下方「阿里云百炼」一节），这样密钥和模型配置可以固化在本地，不必每次开窗口设环境变量。用 `SE_AGENT_ENV_FILE` 可指向别的密钥文件。界面里保存的设置在服务重启后仍然会回落到这份启动配置。

## 赛马、评审与任务分解联动预览

```bash
python -m se_agent.workbench_preview --port 8003
```

打开 http://127.0.0.1:8003，确认需求快照，设置提示词并启动赛马。草案齐备后点击「进入评审与整合」，同版需求与所有参赛组草案会自动交接。再生成独立评价、选定任一组或融合，人工检查并确认，确认后可下载规格 JSON 或 Markdown，也可点击「进入任务分解」把确认版直接交给 QLM 分解器。

左侧目录可在赛马和评审之间切换，保留本次页面上的输入。赛马主理人可以暂停派发、给指定组补充指令并单独重跑。评审主理人可以检查当前编辑、定位未决事项，也能把返工指令送回指定小组，由人工确认是否应用。同一需求快照的返工会递增评审轮次，在「版本与记录」中保留旧方案、原草案和本轮主张差异。不同候选做法会列成议题。采用选项或填写人工答复并写入决策后，保存时由服务端生成正文。评审和任务计划存于内存，重启前可将计划导出。

任务页可修改名称、执行角色、分钟级估时、前置依赖和人工审核要求，也可新增任务。每项任务关联需求编号，适用时带上决策编号和未决项编号。保存时检查规格版本、前置任务编号和循环依赖。保存后可查看依赖图，或下载同版的 `workflow.json` 与 `task.md`。这两个文件用于后续编排交接。当前预览止于任务分解与计划导出。

### 接入生成与评审模型

默认是离线模拟。配置兼容 Chat Completions JSON 模式的服务后，独立构思、组内质疑、草案、评分与整合都使用模型。每组调用只接收自己的提示词，评审独立接收一份草案。出错后显示失败并支持重试。

以下示例中的模型名需替换成你自己的模型。

```powershell
$env:SE_AGENT_BASE_URL = "http://127.0.0.1:11434/v1"
$env:SE_AGENT_MODEL = "<已安装或可调用的模型名>"
python -m se_agent.workbench_preview --port 8003
```

需要鉴权时在本机配置 `SE_AGENT_API_KEY`。配置地址后，当前需求与草案会发送给该模型服务。接口格式参考 [Ollama 官方兼容文档](https://github.com/ollama/ollama/blob/main/docs/api/openai-compatibility.mdx)。

## HSX · 评审与方案整合原型

负责人：洪少炫，开发分支 `HSX`。接收同版本需求和至少两份不同小组草案，完成独立评价、方案取舍、人工编辑确认与交接导出。使用离线回调，无需依赖和模型密钥，原 v1 演示保持可用。

```bash

```

打开 http://127.0.0.1:8002，加载取舍演示或导入 CLY 交接 JSON。详见 [运行、接口与验收说明](docs/评审与方案整合.md)。

Windows 可双击 start-local.cmd，然后在浏览器打开 http://127.0.0.1:8008。关闭启动窗口可停止服务。

Windows 双击 start-local.cmd 后打开 http://127.0.0.1:8008。右上角按钮可选择「本地模拟」或「真实使用 / 配置 API」。本地模拟使用新版 HTML 的内置案例，模式切换会重新加载页面。真实使用连接本机工作台及 SQLite 项目数据；请在配置表单测试并保存模型设置。实际 Git 执行还需要按整合运行说明配置目标仓库。内置案例的自动审查与回退是模拟数据。

### 运行生成项目的模块测试

设置 `SE_AGENT_TEST_IMAGE` 为本地 Docker 镜像名。镜像需提供 Python 和 Node.js，以及生成应用的测试依赖。工作台会在无网络、只读挂载的容器中运行当前任务的 `unittest` 或 `node:test`，失败时退回任务，等待修复后再提交。未设置时，运行记录会将生成的测试标为待实跑。
